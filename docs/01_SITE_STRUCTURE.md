# totte Screen / State Inventory

更新日：2026-10-10  
対象：初期制作範囲（PC 1440px、Mobile 390pxを主軸）

## 1. 画面構成

| 画面 | 目的 | 主要操作 | 主な情報 |
|---|---|---|---|
| ダッシュボード | 営業状況と、いま必要な対応を短時間で把握する | 在庫確認、発注管理へ移動 | 対象日の売上・客数・客単価、7日間の売上、要補充、入荷待ち |
| 売上分析 | 選択期間の傾向と前期間との差を確認する | 期間選択、日別推移の確認 | 売上・客数・客単価、同日数の直前期間比、日別推移 |
| 在庫管理 | 現在庫と補充基準、入荷待ち数量を並べて判断する | 絞り込み、品目を選んで発注作成 | 品目、カテゴリ、現在庫、補充基準、入荷待ち、在庫状態 |
| 発注管理 | 発注済みと入荷済みを管理し、入荷を在庫へ反映する | 新規発注、内容確認、発注確定、入荷処理 | 発注番号、品目、数量、発注日、入荷予定日、ステータス |

## 2. 共通フレーム

- 左サイドバー：正式な `totte` ロゴ、4画面のナビゲーション、現在の店舗。
- 上部ヘッダー：店舗切り替え、利用者メニュー。選択店舗は全画面で維持する。
- 店舗名：中央通り本店、北口駅前店、水辺公園店。
- メイン領域：画面名、説明、画面固有の対象時点または主要操作。
- 売上の日付・期間は売上情報だけに適用する。
- 在庫管理と発注管理は「現在」の状態であることを画面上に明記する。
- モバイルは上部にロゴシンボル・店舗選択・利用者、下部に4画面ナビゲーションを配置する。
- モバイルではPCの多列表をカードへ変換し、横スクロールなしで品目・状態・操作を確認できるようにする。
- 768pxは72pxのアイコン主体ナビゲーションレールを使用し、一覧を原則2列カードで表示する。
- 1024pxは184pxの簡潔なサイドバーを使用し、一覧は判断に必要な優先列へ絞った表で表示する。

## 3. 画面別の構成と状態

### 3.1 ダッシュボード

構成：売上・客数・客単価、7日間の売上推移、要補充の在庫、入荷待ちの発注。

主要状態：

- 通常：対象日の数値と、現在の在庫・発注を表示。
- 客数0：客単価を「—」で表示。
- 要補充なし：空状態の文言と在庫管理への導線を表示。
- 入荷待ちなし：空状態の文言を表示。

### 3.2 売上分析

構成：期間選択、売上・客数・客単価、日別売上推移、日別明細。

主要状態：

- 初期期間：直近7日間。
- 期間変更：選択した日数と同じ日数の直前期間を比較対象にする。
- データなし：数値は0、客数0の場合の客単価は「—」、グラフと明細は空状態を表示。
- 入力エラー：終了日が開始日より前など、無効な期間を項目近くの文言で示す。

### 3.3 在庫管理

構成：更新時点、件数サマリー、検索、状態・カテゴリ絞り込み、在庫一覧。

一覧列：品目サムネイル・品目名、カテゴリ、現在庫／補充基準ゲージ、入荷待ち、在庫状態、操作。

主要状態：

- 通常：在庫状態を「適正」で表示。
- 要補充：現在庫が補充基準以下。アンバー、アイコン、文字を併用する。
- 入荷待ちあり：現在庫とは別の列に数量を表示し、重複発注へ注意できるようにする。
- 絞り込み後0件：条件を解除できる空状態を表示。
- 発注作成への遷移：選択店舗と品目を発注フォームへ引き継ぐ。

### 3.4 発注管理

構成：更新時点、ステータス件数、検索・ステータス絞り込み、発注一覧、新規発注。

一覧列：発注番号、品目、数量、発注日、入荷予定日、ステータス、操作。

主要状態：

- 発注済み：入荷処理が可能。
- 入荷済み：入荷処理は無効化し、処理済みであることを文字で示す。
- 新規発注フォーム：店舗、品目、現在庫、入荷待ち、発注数量を表示。
- 入力エラー：未選択、0以下の数量などを項目近くに表示。
- 発注確認：店舗・品目・仕入先・単位・数量・入荷待ちを確定前に再確認。
- 発注完了：完了通知を表示し、一覧へ反映。
- 入荷確認：対象発注と在庫へ加算される数量を表示。
- 入荷完了：ステータスを入荷済みに変更し、在庫数へ一度だけ反映。
- 進行表示：「内容入力 → 確認 → 発注完了 → 入荷待ち → 入荷済み」の5段階を共通表示。

## 4. 主要導線

`ダッシュボードの要補充 → 在庫管理の対象品目 → 発注フォーム → 発注確認 → 発注完了 → 発注済み一覧 → 入荷確認 → 入荷完了 → 在庫へ数量反映`

引き継ぐ情報：

- 全画面：選択店舗。
- 在庫管理から発注：店舗、品目。
- 発注から入荷：発注番号、店舗、品目、発注数量。

## 5. 共通状態の優先度

### P0：主要導線に必須

- 通常、選択、フォーカス、入力エラー、確認、完了。
- 発注済み／入荷済み。
- 要補充／適正。
- 入荷済みの再処理不可。

### P1：実装・QAで確認

- 処理中、無効、空状態。
- 検索・絞り込み後0件。
- ブラウザ再読込後の店舗・在庫・発注状態の保持。

PC版ワイヤーフレームでは、発注数量の入力エラー、在庫絞り込み後0件、発注確定の処理中を代表状態として作成済み。

## 6. ワイヤーフレーム制作順

1. PC版4画面の通常状態。
2. 発注作成・確認・完了、入荷確認・完了。完了済み。
3. PC版の空・エラー・無効状態。代表3状態を作成済み。
4. 375 / 390pxの主要導線。390pxの主要4画面と375pxのダッシュボード確認を作成済み。
5. 390 / 768 / 1024 / 1366 / 1440pxの主要4画面と、375pxのダッシュボードを検証済み。
6. 主要導線、画面、状態、Breakpointを画面マップで照合済み。
