# totte Design Rules

更新日：2026-10-11  
状態：ビジュアルデザイン基盤と正式ロゴを確定。主要画面・状態と実装へ適用済み。

## 1. Design principles

1. 店長が「今日の状態」と「次に必要な行動」を短時間で理解できる。
2. 売上・在庫・発注を混同させず、同一画面では意味のまとまりを明確に分ける。
3. 注意や完了を色だけで伝えず、アイコン、文言、ボタン状態を併用する。
4. 操作の前後関係を保ち、店舗・品目の再入力や入荷の二重処理を避ける。
5. 明るく温かい印象を保ちつつ、表・数値・操作の可読性を優先する。

## 2. Layout

### Desktop base

- Artboard：1440 × 1160px（PC版ワイヤーフレーム）
- Sidebar：224px
- Main horizontal padding：32px
- Header：72px目安
- Content max width：サイドバーを除く可用幅内で流動
- Main grid：12 columns / 24px gutter を目安
- Chart : Alert panel：概ね 3 : 2（要件の約60% : 40%）

### Responsive checkpoints

- 375 / 390px：1カラム。左右余白16pxを基本とし、深いグリーンの上部ヘッダーに店舗選択、下部に4画面ナビゲーションを置く。
- ダッシュボードのSP順序：店舗・対象日 → 数値 → 要補充の在庫 → 売上推移 → 入荷待ち。
- 多列のデータ表は横スクロールへ頼らずカードへ変換し、項目ラベル、状態、主要操作を縦方向に並べる。
- 768px：深いグリーンの72pxナビゲーションレールへ切り替える。一覧は2列カードを基本とし、品目画像、状態、主要操作を保持する。
- 1024px：深いグリーンの184pxサイドバーを表示する。一覧はカテゴリや補助日付を必要に応じて省略し、判断に必要な優先列へ絞った表を使う。
- 768 / 1024pxとも横スクロールは使用せず、店舗選択は1366 / 1440pxと同じ白い上部ヘッダーに維持する。
- 1366 / 1440px：224pxのサイドバーとメイン左右32px余白を維持する。3枚のKPIカード、チャートと在庫アラート、多列の一覧を表示する。
- 1366pxは1440pxと同じ情報密度を維持し、メイン領域内の列幅だけを均等に圧縮する。

## 3. Spacing and shape

- Spacing scale：4 / 8 / 12 / 16 / 24 / 32 / 40 / 48px
- Card padding：24px
- Mobile card padding：16px
- Section gap：24px
- Control height：40pxを基本
- Radius：10px（input / button）、16px（card）、20px（modal）、999px（badge）
- Border：1px、低コントラスト。影は必要最小限。

## 5. Typography

- Candidate：`Noto Sans JP`, system sans-serif
- Page title：Desktop 28px / Mobile 24px / 700
- Section title：18px / 700
- KPI value：Desktop 32px / Mobile 26〜28px / 700
- Body / table：14px / 400〜500
- Caption / metadata：12px / 400〜500
- 金額・数量は桁を読みやすくし、単位を省略しない。

## 5.1 Visual direction

- 白いカードとウォームグレー背景の差を、薄い境界線と16pxの角丸で整理する。
- 深いグリーンはサイドバー、主要操作、現在地、当日のグラフへ優先的に使う。
- KPIカードはラベル、カテゴリ別アイコン、数値、前日比を一まとまりにする。
- 正式ロゴは「取っ手」と小文字の `t` を統合したシンボルと、丸い端部の独自ワードマークを使用する。
- Mobileは装飾を減らし、カード、状態、主要操作の読み取りを優先する。

## 5.2 Logo

- コンセプト：「totte＝取っ手」と「必要な情報に手が届く」を、取っ手のアーチと小文字の `t` へ統合する。
- 基本ロゴ：`assets/images/brand/totte-logo-primary.svg`
- 反転ロゴ：`assets/images/brand/totte-logo-reverse.svg`
- シンボル：`assets/images/brand/totte-symbol-primary.svg` / `totte-symbol-reverse.svg`
- Favicon：`assets/images/brand/totte-favicon.svg`
- 基本色：`primary`（`#174D3B`）。濃色背景では白の反転ロゴを使用する。
- 最小サイズ：フルロゴは通常112px幅、モバイルヘッダーでは例外として92px幅、シンボルは18px幅を下限目安とする。
- 画面内サイズ：1366 / 1440pxのサイドバーはフルロゴ112〜116px幅、1024pxは112px幅、768pxのレールはシンボル18〜22px幅、375 / 390pxのヘッダーはフルロゴ92px幅を基準とする。
- 375 / 390pxの上部ヘッダーと、768〜1024pxの左ナビゲーション背景は深いグリーンとし、濃色面のロゴは白い反転版を使用する。768px以上の上部ヘッダーは白背景とする。選択中のナビゲーションは白い面にグリーンのアイコン・文字を組み合わせる。
- 反転ロゴ／反転シンボルのコンポーネント自体には背景色を持たせず、配置先の濃色面で白線を表示する。
- サイドバーではロゴとキャッチコピーの間を8px確保し、ロゴの線と文字を重ねない。
- キャッチコピーはロゴ本体に含めず、用途に応じて独立したテキストとして配置する。
- 変形、縦横比の変更、影・グラデーションの追加、定義外の色への変更は行わない。

## 5.3 Screen-specific emphasis

- ダッシュボード：当日のKPI、要補充、入荷待ちを同一画面で短時間に確認できる階層にする。
- 売上分析：比較グラフを主役にし、選択期間・直前期間の凡例と期間最高値を併記する。
- 在庫管理：要補充、入荷待ち、適正を一覧内で分離し、品目画像、現在庫、補充基準、操作を同じ行で確認できるようにする。
- 発注管理：発注済みと入荷済みを文字・アイコン・背景色で区別し、入荷済みの操作を無効状態にする。

## 5.4 Core workflow states

- 発注作成：店舗と品目を引き継ぎ、品目画像、現在庫、補充基準、入荷待ち、入力値を同じモーダル内で確認できるようにする。
- 発注確認：店舗・仕入先・数量・入荷予定日を並べ、確定後の入荷待ち合計をアンバーの確認面で示す。
- 発注完了：成功アイコン、発注番号、仕入先、数量、入荷予定日、発注状態を表示し、次の行動を「発注一覧へ」にする。
- 入荷確認：`現在庫 + 今回の入荷 = 反映後` を数式状に並べ、在庫へ加算される数量を確定前に確認できるようにする。
- 入荷完了：処理前、入荷数量、現在庫を成功面で示し、ロックアイコンと文言で再処理不可を明示する。
- 5段階表示は、完了済みをチェック、現在を枠付きの数字、未完了を薄い数字で区別する。

## 5.5 Auxiliary states

- 入力エラー：対象入力欄の赤い枠、直下の具体的な理由、フォーム全体のエラー要約を併用し、修正完了まで次の操作を無効にする。
- 空状態：該当0件の理由を見出しと説明で示し、選択中の絞り込み条件を維持したまま「絞り込みを解除」へ戻せるようにする。
- 処理中：進行中の文言とスピナーを表示し、戻る操作と閉じる操作を弱め、確定操作の連続実行を防止する。

## 6. Dashboard components

- Sidebar navigation：現在地は背景、アイコン、文字ウェイトで示す。
- Store selector：全画面共通。現在の店舗名を常に表示する。
- Date control：売上情報へ適用されることが分かる位置へ置く。
- KPI card：名称、値、単位、比較基準（前日比）をセットで表示する。
- Sales chart：期間「過去7日間」、縦軸単位、日付、主要推移を表示する。装飾的な目盛りを増やさない。
- Restock alert：品目、現在庫、補充基準、入荷待ち、操作を表示する。
- Pending order table：発注番号、発注日、品目数、入荷予定、状態、操作を表示する。
- Status：在庫状態と発注状態を別ラベルで扱う。

## 7. Product and data visualization

- 品目は44px角の統一サムネイルで表示する。正式素材は背景透過の商品写真とし、無地パッケージ、柔らかなスタジオ光、暖色寄りの色調で統一する。
- サムネイルは品目名を置き換えず、画像・品目名・カテゴリを一まとまりで表示する。
- 在庫ゲージは現在庫が補充基準を満たしているかを示す補助表現とし、現在庫と補充基準の数値を必ず併記する。基準以上は100%で上限表示する。
- 入荷待ちはトラックアイコン、数量、「入荷待ち」の文言を組み合わせ、現在庫および在庫状態とは別項目として表示する。
- 売上比較グラフは選択期間を深いグリーン、同じ日数の直前期間を薄いグレーで併記する。期間最高日は文言付きのコールアウトで示す。
- 発注から入荷までは「内容入力 → 確認 → 発注完了 → 入荷待ち → 入荷済み」の5段階で表示する。完了済み、現在、未完了を色だけでなくチェック、数字、ラベルで区別する。

## 8. Required states

- Button：Default / Hover / Focus / Disabled / Processing
- Input：Default / Focus / Error / Disabled
- Inventory：適正在庫 / 要補充
- Order：発注済み / 入荷済み
- Modal：確認 / 処理中 / 完了
- Data area：Loading / Empty / Error
- Toast：成功 / 失敗

## 9. Accessibility notes

- 警告はアンバーだけでなく、警告アイコンと「要補充」の文言を併用する。
- KPIの増減は矢印・符号・比較ラベルを併用する。
- Interactive targetは原則40px以上を確保する。
- Focus表示を消さず、キーボード操作順を視覚順と一致させる。
- 表の見出し、単位、状態を省略しない。
- 品目画像には品目名を隣接させ、画像だけで識別を要求しない。
- 在庫ゲージと売上グラフには、判断に必要な数値・単位・比較期間を併記する。
